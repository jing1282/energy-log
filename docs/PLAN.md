# 能量记录 PWA 计划

## 目标
- 通过记录了解自己的波动情况(节律、高低点、什么情况下容易起伏),据此建立更匹配的适应行为:知道自己什么时候该推进、什么时候该放慢、用什么方式恢复。
- 因此 App 的重点是“看见波动并找到自己的应对方式”,不是打分本身,也不是追求把每天都维持在高位。

## 设计原则
- 记录不能成为负担:首页只放要输入的必要项,其余收进折叠区,所有项目都可跳过,可以只记一个分数就离开。
- 不制造假数据:没填就是“未记录”(null),统计时一律排除,不当作 0,也不默认成“舒适”或“没锻炼”。
- 算法简单、透明、可调:所有规则和阈值能在界面上看到说明,并作为可调整的产品规则。
- 不下医学结论,不暗示因果:文案用“在你的记录中平均更高/更低”,提示以鼓励和留出恢复空间为主。

## 技术与形态
- Next.js + TypeScript + Tailwind + shadcn/ui,静态导出,做成 PWA(可添加到 iPhone 主屏幕,全屏运行,可离线)。
- 数据存本机 IndexedDB(Dexie),无账号、无后端。
- 图表用 Recharts。
- iOS 注意点:只有“添加到主屏幕”后,Safari 才会较稳定保留数据,所以必须提供 JSON 导出和导入备份,并在首次打开时提示添加到主屏幕。
- 上线方式:用静态托管(如 Vercel 或 GitHub Pages)得到一个 https 地址,你在 iPhone 上打开并添加到主屏幕。开发阶段在云端机器上起服务预览。

## 数据模型(每天一条记录,缺失值为 null)
- 精力、情绪、压力:1 到 5。
- 赋能事件和耗能事件:标签,每天重新选择;每个标签有分值(默认 1,可调 1 到 3),并可收藏。
- 适应行为:当天做的调整(与赋能事件共用标签),以及调整后感受(好一些、差不多、更不舒服,可稍后补填,可为空)。
- 睡眠:时长和质量。
- 锻炼:有、没有、未记录三态,可选强度。
- 饮食:标签点选,可自定义。
- 冷热体感:很冷、偏冷、舒适、偏热、很热,单选,可不填(热的一侧与冷对称,如需不同请告诉我)。
- 生理周期:月经期、卵泡期、排卵期、黄体期,四个阶段单选,可不填(未选 = 未记录,统计时排除)。
- 燥湿体感:燥、湿,独立多选,可同时选中,可不填。
- 身体状况:胃部感受是留白的自由文字框,没有预设选项,由你用自己的话写下当下的感受,写这个动作本身就是一次回到当下的觉察;另有自定义身体标签,按需记录。
- 备注:一句话,可选。
- 时令:不存储填写项,由日期自动计算(见下)。
- 可选的“随手记当下精力”:一天内追加时间点的打分,不强制。

## 页面
1. **今日(首页,只保留要输入的项目)**
   - 日期旁自动显示时令,例如“秋 · 白露”,只作背景信息。
   - 首页只放需要输入的内容,不放近期收支卡片、曲线、推荐或示例数据横幅(这些分别在“账户”“趋势”“设置”里)。顺序固定为:
     1. 身体觉察:冷热体感五档、燥湿体感多选、胃部感受自由文字、自定义身体标签、生理周期四阶段。
     2. 精力评分(1 到 5)。
     3. 赋能事件。
     4. 耗能事件。
     5. 保存按钮(只记一个分数也能保存)。
   - 底部折叠区“更多”,默认收起:情绪、压力、睡眠、锻炼、饮食、今天的调整与感受、随手记当下精力、备注、沿用上次评分。
   - 所有项目都可以跳过。不自动带入昨天的值:上次评分只作参考,未确认项保持为空,“沿用上次评分”按钮在“更多”里。标签每天重新选择。
   - 保存后给一句温和的反馈,并展示当天的赋能事件。
2. **近期收支(独立的“账户”页,在底部导航里)**
   - 含义:代表“近期充电与消耗的记录”,不代表实际还能撑多久;事件分值是主观设定,不换算成体力储备。
   - 算法:最近 7 个自然日的赋能总分减耗能总分,不衰减,不混入精力评分。
   - 界面说明这是滚动窗口:旧记录退出窗口导致的变化不算当天支出。
   - 阈值是可调整的产品规则,三档只是提示:收支为正、持平、偏负。
   - 低值文案示例:“最近消耗比较多,可以给自己留一点恢复空间”。
   - 当天自评精力单独参与提示:自评偏低时,即使收支为正,也提示可以休息。
   - 页面内容:账户卡片(近 7 天收支与今天自评精力并排,互不覆盖)、你常用的充电方式、按日明细、本周期构成、按周对比。
   - 明细:按日、周展示收入和支出构成。
   - “你常用的充电方式”:早期数据不足以判断效果,先推荐你最常选或收藏的 3 项,不做效果判断。
3. **趋势**
   - 单项波动曲线:精力、情绪、压力、睡眠时长、近期收支,可切换指标,7 天、30 天、90 天、全部。
   - 高低点柔和配色标注,叠加 7 天移动平均,周月对比。
   - 常态化说明(例如“低谷通常两天后回升”)不做预设,只有出现足够多次可比较的波动(暂定至少 3 次)才生成,否则显示中性说明,如“记录越多,这里会越清楚”。
   - 背景带三选一:时令(看季节变化)、生理周期阶段(只连接相邻且阶段相同的已记录日子,未记录的日子留白)、无,避免图面拥挤。
   - 曲线只在趋势页(首页不再放 14 天曲线)。
4. **关联洞察**
   - 范围:睡眠、压力、情绪、锻炼、饮食标签、冷热、燥湿、生理周期、各赋能和耗能事件与精力的关系。冷热档位较多,样本少时先合并成“偏冷及以下”“舒适”“偏热及以上”再比较。
   - 胃部感受是自由文字,只用于回看和搜索,不参与自动统计,避免把你的觉察硬塞进分类。
   - 样本规则:两组分别判断,例如“有锻炼”对比“明确没锻炼”,两组各至少 7 条有效记录才展示差异,并同时显示两组数量。未记录不进入任何一组。
   - 次日关联只匹配相邻自然日,不跨过漏记的日期。
   - 冷热和燥湿分开分析,也可看组合,如“冷加湿”“热加燥”,每个组合同样要满足样本数。
   - 生理周期按四个阶段分组比较精力:每个阶段至少 7 条有效记录才参与比较,至少两个阶段达标才展示差异,并同时显示各阶段的记录数;未记录阶段的日子不进入任何一组,措辞非因果。同一天和次日两种视角都有。
   - 措辞用“在你的记录中平均更高/更低”,不解释成因果。
5. **适应行为记录(很轻,和赋能事件共用标签)**
   - 今天做了什么调整:早点休息、减少安排、散步、保暖、调整饮食等,可自定义。在打卡的可展开区点选,和赋能事件共用同一套标签,不重复填写。
   - 调整后的主观感受:好一些、差不多、更不舒服,可稍后补填,不强制。
   - 允许记录“原本想给自己充电,这次却没有帮助”,这样才能看出同一个行为在不同状态下是否适合你。
   - 当天状态(精力、体感、时令、睡眠等)自动与这次调整关联,无需另外填写。
6. **波动回看与个人线索(系统核心)**
   - 回看重点回答三个问题:我怎样波动(精力、体感、胃部文字的变化与重复模式);什么情况下容易变化(时令、体感、睡眠、活动与低谷和回升的伴随);怎样调整更适合当时的我(相似状态下,哪些调整被你多次评为“好一些”)。
   - 线索举例:“你在‘冷加湿’的记录中,有 N 次精力偏低。其中尝试保暖的 M 次里,有 K 次标记为‘好一些’,可以继续观察。”
   - 每条线索都附样本量,并能点开原始记录;样本不足时不展示,措辞只说“在你的记录中”,不把偶然重合当成结论。
   - 能量账户保留为鼓励入口,波动回看和适应行为是核心。衡量是否有帮助:你是否更能理解当下的自己、更容易选择合适的安排。
7. **设置**
   - 管理标签(增删改、赋能或耗能分类、分值、收藏)。
   - 示例数据的载入与清除入口(首页不再放示例横幅),以及添加到主屏幕的说明。
   - 调整近期收支的阈值。
   - 导出和导入 JSON 备份、清空数据。
   - 提醒:iOS 对网页应用推送限制多,第一版不做推送,改为引导你用 iOS 快捷指令或日历设置每晚提醒。

## 时令标注规则
- 季节与二十四节气由日期在本地自动计算,不需要网络,不需要用户填写。
- 节气日期按天文算法计算(同一节气每年可能相差一天),显示“季节 · 当前所处节气”,例如“秋 · 白露”。
- 作为背景信息,用于首页日期旁和趋势图背景,也可在回看历史时查看当日时令。

## 实施步骤
1. 脚手架:Next.js 静态导出、Tailwind、shadcn/ui,配置 PWA,固定一个不常见端口起预览服务。
2. 数据层:Dexie 表结构、缺失值处理、导出和导入。
3. 今日打卡(分层填写)和标签管理。
4. 时令计算与显示。
5. 体感、生理周期与身体状况记录。
6. 近期收支与“常用充电方式”(独立“账户”页)。
7. 趋势页。
8. 关联洞察页,含样本数规则。
9. 内置示例数据,含缺失值和三态,可一键载入和清除。
10. 适应行为记录(轻量,共用标签)与波动回看、个人线索(放在趋势和洞察之后,数据积累后才有意义)。
11. 移动端打磨、手机视口验证、README(运行方式、添加到主屏幕、备份说明、产品规则)。

## 暂不做
- 账号、登录、云同步、多设备同步、原生 iOS App、推送通知、AI 分析、按天气 API 自动取气象数据。
- 暂缓到第二版(用一段时间、确实想要再加):自写的“当 X 时我试试 Y”规则与触发提示、每周回顾页。

## 需要你留意
- 数据只存在这台手机上,换手机或清除网站数据会丢失,所以靠导出备份。
- 本 App 是自我觉察工具,不替代体检和就医。
